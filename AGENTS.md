## 🤖 Контекстна інженерія (Context Engineering)

### 1. Динамічний контекст замість статичних дампів
- **ЗАБОРОНЕНО** користуватись `repomix-output.xml`, `repomix-output-md`, або іншими статичними дампами коду як джерелом контексту для аналізу.
- **ЗАБОРОНЕНО** покладатись на закешовані файли `.codegraph/`, `*.snapshot.*`, або інші статичні індекси, які можуть бути застарілими.
- **ОБОВ'ЯЗКОВО** для навігації по коду використовуй динамічні інструменти:
  - **`grep`** — для лексичного пошуку за текстом, патернами, селекторами
  - **`glob`** — для пошуку файлів за шаблоном
  - **`read`** — для точків входу та конкретних файлів (лише ті, що потрібні)

### 2. Воркфлоу Research → Plan → Implement → Verify (RPI)
1. **Research** — знайди точку входу, пройди граф викликів динамічно (grep → read → grep). Не намагайся вгадати архітуру.
2. **Plan** — згенеруй план змін у Short-Term Memory перед написанням коду.
3. **Implement** — пиши код, дотримуючись існуючих патернів та конвенцій.
4. **Verify** — запусти `npm run lint`, `npm run test`, `npm run build` після кожного змінення.

## 🐛 Протокол дебагінгу Chrome Extensions

### 3. НЕ діагносувати "наощіп" — використовуй DevTools
- **ЗАБОРОНЕНО** виправляти баги Content Scripts, Background Service Workers або UI-логіку, не маючи діагностичних даних.
- Якщо розширення не працює, ти **ЗОБОВ'ЯЗАНИЙ**:
  1. Запустити режим розробки: `npm run dev`
  2. Встановити розпаковану розширення у Chrome (`chrome://extensions/` → "Режим розробника" → "Завантажити розпаковану програму")
  3. Відкрити DevTools (F12) на цільовій сторінці
  4. Перевірити вкладини: **Console** (помилки маніфесту, CORS), **Network** (записи background script), **Application → Service Workers** (стан service worker)
  5. Провідати `console.log` у реальному часі або просити користувача надати логи з консолі

### 4. Діагностичний скрипт для користувача
- Якщо не маєш доступу до браузера, **обов'язково надай готовий JS-скрипт** для консолі DevTools (F12) та попроси користувача вставити та надати результат.
- Приклад шаблону:
```js
// Вивід помилок розширення
console.log('Extension errors:', (await chrome.runtime.getLastError?.()));
// Перевірка DOM-елементів
console.log('Target elements:', document.querySelectorAll('/* selector */'));
```

## 📐 Правила розробки
- Chrome Extension (Manifest V3) на TypeScript / Vite.
- Перевіряй відсутність помилок збірки, лінтера та тестів (`npm run lint` && `npm run test` && `npm run build`) після внесення змін.
- **Scoping & CSS Rules**:
  - Усі DOM event listeners у скриптах попапу/опцій повинні бути строго розташовані всередині `$(document).ready(...)` або `DOMContentLoaded`.
  - Усі CSS правила повинні перевірятися на відсутність висячих атрибутів та синтаксичних дужок (`npm run test` включає `css_lint.test.js`).
- **Manifest V3**: `host_permissions` та `content_scripts.matches` вже налаштовані на конкретні домени (`streamyard.com`, `*.youtube.com`, `studio.youtube.com`) — не розширюй до `<all_urls>`.
