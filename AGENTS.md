## 🤖 Контекстна інженерія (Context Engineering)

### 1. Динамічний контекст замість статичних дампів
- **ЗАБОРОНЕНО** користуватись статичними дампами коду чи зрізами проєкту як джерелом контексту для аналізу.
- **ЗАБОРОНЕНО** покладатись на закешовані файли `.codegraph/`, `*.snapshot.*`, або інші статичні індекси, які можуть бути застарілими.
- **ОБОВ'ЯЗКОВО** для навігації по коду використовуй динамічні інструменти:
  - **`grep`** — для лексичного пошуку за текстом, патернами, селекторами
  - **`glob`** — для пошуку файлів за шаблоном
  - **`read`** — для точків входу та конкретних файлів (лише ті, що потрібні)

### 2. Воркфлоу Research → Plan → Implement → Verify (RPI)
1. **Research** — знайди точку входу, пройди граф викликів динамічно (grep → read → grep). Не намагайся вгадати архітуру.
2. **Plan** — згенеруй план змін у Short-Term Memory перед написанням коду.
3. **Implement** — пиши код, дотримуючись існуючих патернів та конвенцій.
4. **Verify** — запусти `npm run lint`, `npm run test`, `npm run build` після кожного змінення.

## 📐 Правила розробки
- Chrome Extension (Manifest V3) на TypeScript / Vite.
- Перевіряй відсутність помилок збірки, лінтера та тестів (`npm run lint` && `npm run test` && `npm run build`) після внесення змін.
- **Scoping & CSS Rules**:
  - Усі DOM event listeners у скриптах попапу/опцій повинні бути строго розташовані всередині `$(document).ready(...)` або `DOMContentLoaded`.
  - Усі CSS правила повинні перевірятися на відсутність висячих атрибутів та синтаксичних дужок (`npm run test` включає `css_lint.test.js`).
- **Manifest V3**: `host_permissions` та `content_scripts.matches` вже налаштовані на конкретні домени (`streamyard.com`, `*.youtube.com`, `studio.youtube.com`) — не розширюй до `<all_urls>`.
- **Polymer Virtualization (`<iron-list>`)**:
  - Пам'ятай про рециклінг DOM-вузлів YouTube Studio (`<iron-list>`). При скролі DOM-вузли перевикористовуються, а `MutationObserver` на `childList` не спрацьовує.
  - Детальний протокол див. у Скілі: `.agents/skills/polymer-virtualization-handling/SKILL.md`.
- **Нативні помилки YouTube Studio (`Error: rp at a.maybeShowTooltip`)**:
  - Наведення курсору на серце автора (`#creator-heart`) викливає нативну помилку YouTube Studio `Error: rp`. Не намагайся приглушувати або приховувати її штучно. Перехоплення `contextmenu` у Capture Phase забезпечує 100% працездатність кнопок розширення незалежно від цієї нативної помилки.

## 📌 Ретроспектива та задокументований досвід: "Біль ходіння по колу"

### ⚠️ Проблема мікро-поправок замість первинної діагностики
У попередніх ітераціях розробки ШІ-асистенти робили понад 20 спроб вирішити баги у YouTube Studio (злітання прапорців при скролі, непрацюючий ПКМ, збої смайликів).
**Головна помилка ШІ була в наступному:**
1. ШІ одразу кидався змінювати код та підганяти селектори/хеші наосліп ("в бій без розвідки").
2. ШІ робив мікро-поправки по міліметру, виправляючи симптоми замість першопричини.
3. Це призводило до ходіння по колу: одне полагоджено — інше відвалилося.

### 💡 Витягнуті уроки та зафіксована специфіка YouTube Studio:
1. **Polymer `<iron-list>` recycling**: Вузли DOM не додаються/не видаляються при скролі. Рециклюється вміст ~20 існуючих вузлів. `MutationObserver` на `childList` мовчить. Реакція на скрол має бути через Capture-phase scroll listener.
2. **Смайлики Polymer**: Смайлики у YouTube Studio — це `<img>` елементи з атрибутом `alt="🙏"`. Простий `textContent` повертає порожній рядок (`""`). Потрібно обов'язково обходити `alt`-атрибути зображень!
3. **Обробка подій ПКМ (contextmenu)**: Події contextmenu на окремих елементах втрачаються при скролі та рециклінгу. **Єдине 100% стабільне рішення** — це глобальний Capture-Phase обробник на `window` (`window.addEventListener('contextmenu', ..., { capture: true })`) з викликом `e.stopImmediatePropagation()`.
4. **Нативна помилка `Error: rp at a.maybeShowTooltip`**: YouTube Studio під час наведення на серце автора генерує помилку у своєму JS. Не слід її чистити чи зрізати; capture-phase обробник розширення працює незалежно від неї.
