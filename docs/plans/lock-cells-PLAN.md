# План: фіксація (блокування) клітинок при перегенерації
### Вкладка «Проєкти» → сітка розкладу → панель перегенерації

> **Статус документа:** проєктна специфікація + план робіт. Готується до виконання ШІ-агентами по лотах (див. `LOTS.md`).
> **Мова інтерфейсу:** українська. **Термін у UI:** «зафіксувати / фіксація» (не «заблокувати» — «блокувати» в UI читається як «заборонити доступ», а тут сенс «закріпити, щоб не змінювалось»). У коді — `lock` / `locked` / `lockedCells`.

---

## 1. Задача

При перегенерації розкладу користувач має вміти **закріпити частину клітинок**, щоб генератор їх не чіпав, а перебудував лише решту.

Способи фіксації, які треба дати:

| # | Дія | Як робиться |
|---|-----|-------------|
| 1 | **Усі клітинки** одним натисканням | кнопка «Зафіксувати всі» в панелі + кутова клітинка сітки |
| 2 | **Один день** | клік по заголовку дня (шапка колонки) |
| 3 | **Усього вчителя** | клік по заголовку рядка (ім'я вчителя) |
| 4 | **Виділення мишкою** | режим фіксації: клік по клітинці — перемикає; затиснута кнопка + протягування — «малює» фіксацію по клітинках |

Плюс те, без чого фіча не буде професійною: зняття фіксації тими самими жестами, скасування дії (Undo), збереження між сесіями, чесна поведінка генератора (жорстке обмеження, а не «побажання»), клавіатура і доступність.

---

## 2. Ключові рішення (і чому саме так)

### 2.1. Окремий «Режим фіксації», а не постійне перемикання по кліку
У сітці розкладу клік по клітинці вже щось означає (відкрити/перетягнути урок). Якщо клік почне ще й фіксувати — користувач ламатиме собі розклад випадково.

**Рішення:** тумблер `🔒 Режим фіксації` в панелі (гаряча клавіша `L`). Поки він увімкнений:
- сітка отримує рамку-підсвітку і статус-смужку зверху («Режим фіксації: клікайте або протягуйте по клітинках»);
- курсор змінюється на «замок»;
- звичайне редагування клітинок вимкнене (щоб не було двозначності).

**Плюс аварійний шлях без режиму:** `Alt` + клік по клітинці фіксує/знімає фіксацію будь-коли, не входячи в режим. Для тих, хто вже звик.

### 2.2. Малювання «за першою клітинкою» (paint-by-first-cell)
Класична поведінка з Excel/сапера, найменш дратівлива:

- натиснув на **незафіксовану** клітинку → уся протяжка **фіксує**;
- натиснув на **зафіксовану** → уся протяжка **знімає** фіксацію;
- напрямок протяжки будь-який, повторний прохід по вже обробленій клітинці нічого не змінює (немає «мерехтіння» від toggle).

Модифікатори, що перебивають правило:
- `Alt` під час протяжки — примусово **фіксувати**;
- `Ctrl`/`Cmd` — примусово **знімати**;
- `Shift` — **прямокутне** виділення від якірної клітинки до поточної, з живим прев'ю, застосовується на відпусканні.

### 2.3. Заголовки як кнопки масових дій
Не додаємо купу кнопок у панель. Використовуємо те, що вже є на екрані:

- **кутова клітинка** (перетин шапок) — усе;
- **заголовок дня** — весь день;
- **заголовок рядка (вчитель)** — усі його клітинки;
- **заголовок конкретного уроку в дні** (напр. «Пн · 3-й урок») — ця колонка.

Кожен заголовок показує **трьохстанний індикатор**: порожній / частково (риска) / зафіксовано (замок), і лічильник при наведенні («12 / 30»). Клік перемикає весь набір: якщо зафіксовано не все — дофіксовує все; якщо все — знімає.

### 2.4. Фіксація порожньої клітинки — це теж фіксація
Зафіксована порожня клітинка означає «тут має лишитись вікно, не став сюди урок». Це потрібно для вікон/методичних днів. У UI показуємо штрихування + бліде «—» і підказку «Залишиться порожньою».

### 2.5. Ніякого кольору-одинака
Зафіксована клітинка = **тінт + діагональне штрихування + іконка замка**. Так її видно у ч/б друці, при дальтонізмі й у темній темі. Легенда — під сіткою, згорнута.

### 2.6. Фільтри поважаються
Якщо на сітці стоїть фільтр (напр. показані 4 з 12 вчителів), масові дії діють **лише на видиме**, і діалог це прямо каже: «Діє на 4 з 12 вчителів (активний фільтр)». Мовчазна фіксація невидимого — джерело найгірших багів довіри.

## 3. Модель даних

```
CellKey = `${teacherId}|${dayId}|${slotId}`     // стабільний, без індексів масивів

ProjectLocks {
  version: 1,
  updatedAt: ISO,
  cells: CellKey[]          // на диску — плаский масив
}
```

- **У пам'яті:** `Set<CellKey>` + похідні лічильники по днях/вчителях (перераховуються ліниво, з кешем).
- **Збереження:** в проєкт (`project.lockedCells`), дебаунс 400 мс, оптимістично; при помилці — відкат + тост «Не вдалося зберегти фіксації».
- **Міграція:** при завантаженні відкидаємо ключі на вчителів/дні/уроки, яких уже немає; лічимо скільки відкинули → в лог/телеметрію. Стара версія формату → апгрейд.
- **Undo:** лише клієнтський, у пам'яті сесії, до 50 кроків, кожна масова дія й кожна протяжка — **один** крок.

## 4. Контракт з перегенерацією

1. Кнопка «Перегенерувати» показує біля себе чип: **«Зафіксовано 42 з 300»**.
2. Перед стартом — прев'ю-діалог: скільки клітинок перебудується, скільки лишиться. Чекбокс «Більше не показувати».
3. Зафіксовані клітинки йдуть у генератор **жорстким обмеженням** (не «вагою»).
4. Після генерації — **перевірка постфактум**: усі зафіксовані клітинки мають бути ідентичні до генерації. Розбіжність — це баг, і його треба ловити тестом і телеметрією, а не очима.
5. Якщо солвер не зміг задовольнити обмеження — **не мовчати й не скидати фіксації самовільно**: показати, які саме фіксації конфліктують (підсвітити червоним + список), і дати дію «Зняти конфліктні фіксації та повторити».
6. Поки йде генерація — уся панель фіксації в read-only з підказкою.

## 5. Продуктивність

Орієнтир: 120 вчителів × 5 днів × 8 уроків ≈ **4 800 клітинок**, стеля — 20 000.

- Протяжка не має ререндерити сітку: під час `pointermove` міняємо **лише CSS-клас** зачеплених клітинок, батчимо у `requestAnimationFrame`.
- Стан — зовнішній стор із точковою підпискою на клітинку (`useSyncExternalStore` / аналог), а не пропси зверху.
- Бюджет: кадр протяжки **< 8 мс** на 20 000 клітинок; масова дія «усі» **< 150 мс** до першого відмальованого кадру.
- Якщо сітка віртуалізована — hit-test через `elementFromPoint`, а не через посилання на всі DOM-вузли.

## 6. Клавіатура і доступність

| Клавіші | Дія |
|---|---|
| `L` | увімк/вимк режим фіксації |
| `←↑↓→` | переміщення по сітці (roving tabindex) |
| `Space` | зафіксувати/зняти поточну клітинку |
| `Shift` + стрілки | розширити виділення |
| `Ctrl` + `A` | усі видимі клітинки |
| `Shift` + `Space` | увесь рядок (вчитель) — як в Excel |
| `Ctrl` + `Space` | уся колонка (урок) |
| `Ctrl` + `Z` / `Ctrl` + `Shift` + `Z` | скасувати / повторити |
| `Esc` | скасувати поточну протяжку; вдруге — вийти з режиму |

Плюс: `role="grid"`/`gridcell`, стан у `aria-label` («Іваненко, понеділок, 3-й урок, зафіксовано»), результати масових дій — в `aria-live="polite"`, контраст рамки/штрихування ≥ 3:1, повага до `prefers-reduced-motion`.

## 7. Етапи і оцінка

| Етап | Зміст | Оцінка | Лот |
|---|---|---|---|
| 0 | Розвідка коду, технічна специфікація під реальний стек | 0.5 д | ЛОТ 0 |
| 1 | Стор фіксацій, ключі, збереження, міграція, unit-тести | 1–1.5 д | ЛОТ 1 |
| 2 | Візуальна мова клітинки, токени, легенда, темна тема | 0.5 д | ЛОТ 2 |
| 3 | Масові дії: усе / день / вчитель / колонка, трьохстанні заголовки | 1 д | ЛОТ 3 |
| 4 | Режим фіксації + малювання мишкою/тачем, прямокутник, автоскрол | 1.5–2 д | ЛОТ 4 |
| 5 | Undo/Redo, тости зі «Скасувати», статус-смужка | 0.5–1 д | ЛОТ 5 |
| 6 | Інтеграція з перегенерацією, прев'ю, конфлікти | 1–1.5 д | ЛОТ 6 |
| 7 | Клавіатура і доступність | 0.5–1 д | ЛОТ 7 |
| 8 | Локалізація і тексти | 0.5 д | ЛОТ 8 |
| 9 | Продуктивність, e2e-тести, телеметрія | 1 д | ЛОТ 9 |
| 10 | Ревʼю UX + коду, поліш | 0.5 д | ЛОТ 10 |
| | **Разом** | **8.5–11 днів** | |

**Порядок і паралелізм:** ЛОТ 0 → ЛОТ 1 → далі ЛОТ 2 і ЛОТ 3 можна паралельно; ЛОТ 4 після 1+2; ЛОТ 5 після 3+4; ЛОТ 6 після 1; ЛОТ 7–9 в кінці; ЛОТ 10 останній.

**Мінімальний корисний зріз (якщо треба швидко):** ЛОТ 0 + 1 + 2 + 3 — уже дає «усі / день / вчитель» і збереження. Малювання мишкою (ЛОТ 4) — окремим релізом.

## 8. Приймальний чекліст

- [ ] Одна кнопка фіксує/знімає всі видимі клітинки; при частковій фіксації показує коректний стан.
- [ ] Клік по дню фіксує весь день; повторний — знімає.
- [ ] Клік по вчителю фіксує весь його рядок; повторний — знімає.
- [ ] Затиснута миша + протяжка фіксує серію клітинок; напрямок значення не має.
- [ ] Протяжка, що почалась із зафіксованої клітинки, — знімає фіксацію.
- [ ] `Shift` + протяжка дає прямокутник з живим прев'ю.
- [ ] `Esc` під час протяжки повертає все як було.
- [ ] Протяжка за край сітки автоматично прокручує її.
- [ ] Працює на тачскріні (планшет).
- [ ] Одна протяжка = один `Ctrl+Z`.
- [ ] Фіксації переживають перезавантаження сторінки й повернення у вкладку «Проєкти».
- [ ] Після перегенерації всі зафіксовані клітинки не змінились — перевірено автотестом.
- [ ] Конфлікт обмежень показується явно, з дією «зняти конфліктні».
- [ ] Усе доступне з клавіатури; скрінрідер озвучує стан клітинки.
- [ ] 20 000 клітинок: протяжка не лагає (< 8 мс/кадр).
- [ ] Немає жодного жорстко зашитого рядка тексту — усе через i18n.

## 9. Відкриті питання (уточнити на ЛОТі 0)

1. Сітка віртуалізована (рендериться частинами) чи ні? — від цього залежить hit-test у ЛОТі 4.
2. Генератор розкладу вміє **жорсткі** обмеження «ця клітинка фіксована», чи доведеться додавати їх у солвер? — головний ризик усього плану.
3. Проєкт редагують кілька людей одночасно? — якщо так, треба правило злиття фіксацій.
4. Чи потрібні «мʼякі» фіксації («бажано не чіпати»), чи достатньо жорстких? — свідомо винесено за межі цього плану.
5. Рядки сітки — вчителі чи класи (або перемикається)? — «вчитель» у документі означає «сутність рядка».
