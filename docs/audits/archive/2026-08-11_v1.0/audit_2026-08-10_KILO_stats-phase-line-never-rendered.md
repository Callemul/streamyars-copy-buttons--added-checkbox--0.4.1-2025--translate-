# 2026-08-10 — KILO — Латентний баг: вертикальні лінії фаз на графіку статистики майже ніколи не малюються

> **Контекст виявлення:** знайдено під час характеристичного тестування хотспоту Fallow
> `modules/stats_exporter.ts` (CRAP-хотспот №1, `npx fallow health --max-crap 30`),
> закріпленого у `tests/stats_exporter_modal.test.js` (тести 19/20/20a). Баг існував в
> оригінальному коді; підтверджений структурно (аналіз джерел) і фактично — тести
> фіксують, що `prepareChartData(makeSession())` повертає 2 плагіни фаз, але жоден
> із них не малює лінію.
>
> **Статус:** ✅ ВИПРАВЛЕНО (2026-08-11). Замість строгого `labels.indexOf(value)`
> плагін тепер обирає найближчу за часом мітку (див. розділ 5). Поведінку закріплено
> оновленими тестами 19/20/20a — лінії фаз тепер малюються.

---

## 1. Що саме зламано

На графіку глядачів ефіру мали б малюватися дві вертикальні лінії-роздільники фаз —
«Питання» (`phase_questions_start`) і «Молитви» (`phase_prayers_start`). У реальності
**лінія майже ніколи не з'являється**, тому що збіг позиції шукається через строгий
`labels.indexOf(value)`, а значення `value` практично ніколи не співпадає з жодним із
накопичених міток часу.

### Ланцюжок дефекту

**а) Значення фази зберігається в момент кліку — з довільними секундами.**
`modules/stats_tracker.ts` → `markPhase` (рядок 110–135) бере *поточний* текст таймера
в мить натискання кнопки і пише його як старт фази:

```ts
// stats_tracker.ts:117,125,128
const timerText = timerWrapper.innerText.replace(/\n/g, '').trim();
...
session.phase_questions_start = timerText;   // напр. "01:23:47"
session.phase_prayers_start   = timerText;   // напр. "01:31:12"
```

**б) Мітки часу на графіку дискретизуються раз на 60 секунд.**
Той самий таймер зчитується трекером лише кожні `STATS_TRACKING_INTERVAL` (60 000 мс),
і новий вузол додається, тільки коли рядок таймера *змінився* відносно попереднього
(рядок 141–183):

```ts
// stats_tracker.ts:174,177,183
if (lastEntry && lastEntry.time === timerText) return;
session.data.push({ time: timerText, viewers: viewerCount });
...
}, SYH_CONFIG.TIMINGS.STATS_TRACKING_INTERVAL || 60000);
```

Отже збережені мітки — це часи вибірок із кроком 60 с (напр. `"01:23:45"`, `"01:24:45"`,
`"01:25:45"`…). Точне значення `"01:23:47"` із п. (а) серед них практично ніколи не
трапляється.

**в) Плагін шукає позицію строгим збігом рядків.**
`modules/stats_chart_data.ts` → `createPhaseLinePlugin` (рядок 26–54) будує лінію лише
якщо індекс знайдено:

```ts
// stats_chart_data.ts:35-36
const index = labels.indexOf(value);
if (index === -1) return;   // ← вихід, коли фаза не співпадає з міткою
```

Оскільки `value` (п. а) не дорівнює жодній із `labels` (п. б), `indexOf` повертає `-1`,
функція завершується до малювання → **лінія фази не рендериться**.

### Підтвердження тестами (characterization)

`tests/stats_exporter_modal.test.js`:
- тест 19 — `prepareChartData` додає два плагіни фаз, коли встановлені обидва старти;
- тести 20/20a — за реалістичного сесійного набору (`data` із 60-секундним кроком, а
  `phase_*_start` із довільними секундами) жоден плагін не знаходить свій `index`, і
  вертикальна лінія не малюється. Ця поведінка **зафіксована як очікувана** (1-в-1).

---

## 2. Наслідок для користувача

Кнопки «✅ Питання» / «✅ Молитви» змінюють свій підпис і зберігають час у сховищі, але
на побудованому графіку статистики **не видно вертикальних роздільників фаз** — користувач
не бачить, де саме ефір перейшов у блок питань / молитов. Інші дані графіка (крива
глядачів, мітки осі X) коректні.

---

## 3. Ймовірне місце виправлення (НЕ виконується в цьому рефакторингу)

Один із варіантів (поза цим етапом):
1. У `markPhase` округляти/нормалізувати `timerText` до тієї ж дискретизації, що й
   вибірки трекера (напр. обрізати секунди або вирівнювати на ґратку 60 с), АБО
2. у `createPhaseLinePlugin` шукати найближчу мітку (`Math.min` за часом) замість
   строгого `indexOf`.

Обидва варіанти змінюють видиму поведінку графіка → потребують окремого погодження.

---

## 4. Зв'язок із рефакторингом (етап 3)

Після декомпозиції `stats_exporter.ts` логіка збережена без змін:
- `modules/stats_chart_data.ts:26` — `createPhaseLinePlugin` (коментар-попередження додано);
- `modules/stats_chart_data.ts:57` — `prepareChartData` (побудова плагінів фаз);
- `modules/stats_tracker.ts:110` — `markPhase` (запис старту фази);
- `modules/stats_tracker.ts:141` — `startTracking` (60-секундна дискретизація).
Публічний API `SYH_STATS_EXPORTER` не змінився; тести 1731 зелені.

---

## 5. Виправлення (2026-08-11)

Обрано варіант «б» із розділу 3 — пошук найближчої мітки замість строгого збігу,
бо він не залежить від моменту натискання кнопки фази і коректно працює за будь-якої
дискретизації вибірок.

- `modules/stats_chart_data.ts` — `createPhaseLinePlugin` тепер перетворює `value` і
  кожну мітку через `parseTimeToSeconds` (з `./stats_math`) і обирає індекс із
  мінімальною різницею секунд; лінія малюється на цій найближчій мітці.
- `tests/stats_exporter_modal.test.js` — тести 19/20/20a оновлено: замість «не
  малюється» вони тепер стверджують, що лінія малюється на найближчій мітці
  (`drawn.length === 2` для `makeSession()`).
- цей аудит перенесено в `docs/audits/archive/2026-08-11_v1.0/`.

Поведінка: вертикальні роздільники фаз «Питання»/«Молитви» тепер з'являються на
графіку поряд із моментом старту фази. Публічний API не змінився.
