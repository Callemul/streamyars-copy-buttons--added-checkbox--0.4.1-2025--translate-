# YouTube module — список задач для паралельних субагентів

**Дата:** 2026-08-23  
**Джерело:** [2026-08-23_GPT-5_AUDIT.md](./2026-08-23_GPT-5_AUDIT.md)  
**Статус:** backlog, реалізацію ще не розпочато  
**Обсяг:** `youtube/`, `youtube/studio/` і мінімально необхідні shared-модулі.

## 1. Мета

Довести YouTube / YouTube Studio модуль до стабільного стану для:

- довгих сесій і великої кількості коментарів;
- Polymer/iron-list recycling;
- повторних `start → stop → start`;
- SPA-навігації;
- паралельних storage-змін і кількох вкладок;
- передбачуваної роботи одного кліку без дубльованих операцій;
- подальшого масштабування без повного переписування.

## 2. Розподіл моделей

Рекомендації спираються на офіційні сторінки [OpenAI Models](https://developers.openai.com/api/docs/models) і [Codex Subagents](https://learn.chatgpt.com/docs/agent-configuration/subagents): Sol — для складної багатокрокової роботи, Terra — для швидших обмежених задач, Luna — для вузької повторюваної роботи.

| Модель | Reasoning | Використовувати для |
|---|---:|---|
| `gpt-5.6-sol` | `xhigh` | наскрізний lifecycle, event ownership, identity/migration, фінальне рев'ю |
| `gpt-5.6-sol` | `high` | shared API з великим fan-in, атомарність і складні race conditions |
| `gpt-5.6-terra` | `high` | локалізована реалізація, DOM/state/storage інтеграції, browser diagnosis |
| `gpt-5.6-terra` | `medium` | тести на один subsystem, selectors, bounded refactor |
| `gpt-5.6-luna` | `medium` | test discovery, механічні fixtures, документація, перевірки |

Fallback, якщо GPT-5.6 недоступний: `gpt-5.5` з тим самим reasoning effort. Для P0/P1 архітектури не використовувати слабшу модель лише заради швидкості.

### 2.1. Чи є універсальний рівень мислення

Ідеального універсального рівня немає. Якщо потрібно вибрати один без додаткового аналізу, для цього плану ставте **High**: це безпечний компроміс для реалізації та рев'ю, але він буде повільнішим за потрібне для механічних задач і слабшим за `xhigh` на критичній архітектурі.

Практичний fallback за моделлю:

- `gpt-5.6-sol` або `gpt-5.6-terra` → **High**;
- `gpt-5.6-luna` → **Medium**;
- для задач із позначкою `xhigh` → **Extra High** (`xhigh`), не знижувати до Medium;
- **Max/Ultra** у цьому плані не потрібні за замовчуванням: вмикати лише якщо `xhigh` не зміг обґрунтовано розв'язати підтверджену складну проблему.

Відповідність назв у Codex: **Medium** = `medium`, **High** = `high`, **Extra High** = `xhigh`.

## 3. Правила оркестрації

1. У поточному середовищі одночасно доступні чотири слоти: root + максимум **3 субагенти**.
2. Усі агенти працюють в одному worktree. Заборонено паралельно редагувати ті самі файли.
3. Для кожної задачі нижче заданий exclusive file ownership. Виходити за нього можна лише після дозволу root.
4. Не виконувати `git checkout`, `git reset`, `git clean`, rebase або commit. Не чіпати наявні user changes у `modules/video_copier_*` і `tests/video_copier*`.
5. Субагент читає `AGENTS.md`; Studio-агент також повністю читає `.agents/skills/youtube-studio.md`.
7. Не читати старі аудити. Поточний аудит можна використовувати як специфікацію.
8. UI/DOM зміни Studio заборонено робити до фактичного DevTools evidence з `YT-00`.
9. Кожен агент запускає лише targeted checks. Root після кожної хвилі запускає повні `npm run test`, `npm run lint`, `npm run typecheck`, `npm run build`.
10. Кожен handoff повинен містити: висновок, змінені файли, тести, ризики, що лишилось, чи можна запускати наступну хвилю.

### Формат запуску субагента

Завдання нижче самодостатні, тому для model override використовувати:

```text
fork_turns: "none"
model: <із картки>
reasoning_effort: <із картки>
task_name: <із картки>
message: COMMON_AGENT_HEADER + TASK_PAYLOAD
```

### COMMON_AGENT_HEADER

```text
Працюй лише над призначеною задачею в поточному shared worktree.
Спочатку прочитай AGENTS.md; для youtube/studio також прочитай .agents/skills/youtube-studio.md.
Не відкривай старі аудити. Не змінюй файли поза ownership без дозволу root.
Збережи всі наявні user changes. Для редагування використовуй apply_patch.
Не виправляй сусідні проблеми. Додай поведінкові тести, а не лише doesNotThrow/характеризацію.
У кінці поверни: результат, файли, команди перевірки, ризики та точний handoff.
```
