> **Статус:** ⛔ НЕ ВИПРАВЛЕНО. Рефакторинг зберігає поведінку 1-в-1. Виправлення потребує окремого погодження.

## 1. Що саме зламано (з порівнянням реального контракту і того, як його викликали, а також помилками tsc, якщо вони є)

Ключ `syh:popup:active_subtab` оголошений у схемі сховища як **мапа**, але і пишеться, і
читається як **рядок**.

Оголошення (`modules/storage_keys.ts:55`):

```ts
export interface StorageSchema {
    ...
    [STORAGE_KEYS.POPUP_ACTIVE_SUBTAB]?: Record<string, string>;   // ← мапа
    ...
    [key: string]: any;   // ← рядок 61: глушник, який ховає розбіжність
}
```

Фактичні **записувачі** кладуть туди простий рядок — ID аркуша:

| Файл | Рядок | Що записується |
|---|---|---|
| `background/message_router.ts` | 61 | `[STORAGE_KEYS.POPUP_ACTIVE_SUBTAB]: sheetId` — `sheetId` це `message.sheetId`, рядок |
| `youtube/studio/studio_header_counters.ts` | 164 | `[STORAGE_KEYS.POPUP_ACTIVE_SUBTAB]: sId` — рядок |
| `popup/popup_listeners.ts` | 48 | `bindTabSwitcher({ storageKey: STORAGE_KEYS.POPUP_ACTIVE_SUBTAB, ... })` — зберігає значення `data-sheet`, рядок |

Фактичний **читач** очікує рядок (`popup/popup_ui_state_restorer.ts:48`):

```ts
const activeSubtabVal = readStoredValue<string>(result, STORAGE_KEYS.POPUP_ACTIVE_SUBTAB, 'tg_active_subtab');
if (!activeSubtabVal || !SHEET_IDS.includes(activeSubtabVal)) return;
```

Порівняння контрактів:

| Джерело істини | Тип |
|---|---|
| `StorageSchema` (декларація) | `Record<string, string>` |
| Три записувачі (рантайм) | `string` |
| Читач `restoreActiveSubtabUI` (рантайм) | `string` |
| **Висновок** | **Декларація помилкова; рантайм узгоджений сам із собою** |

**Помилок `tsc` немає — і це і є суть проблеми.** `npx tsc --noEmit` дає exit code 0, бо
індексна сигнатура `[key: string]: any;` (рядок 61 у `modules/storage_keys.ts`) поглинає
будь-яке присвоєння. Тобто типізація створює **ілюзію** захисту: поле оголошене строго, але
жоден із трьох записувачів не перевіряється проти нього.

Для контрасту — сусідній ключ оголошений правильно:
`[STORAGE_KEYS.POPUP_ACTIVE_TAB]?: string;` (рядок 54), і він теж зберігає рядок.
Тобто `POPUP_ACTIVE_SUBTAB` — це саме одиничний огріх, а не свідома схема «мапа на аркуш».

## 2. Runtime-наслідки (детальний аналіз та трасування помилки)

### 2.1 Сьогодні поломки НЕМАЄ

Оскільки і записувачі, і читач однаково трактують значення як рядок, поведінка користувача
зараз коректна: активна підвкладка відновлюється. Це підтверджують наявні тести
(`tests/popup_state_restorer.test.js:382`, `tests/popup_ui_state_rules.test.js:170`), які
передають саме рядок:

```js
restoreActiveSubtabUI({ [STORAGE_KEYS.POPUP_ACTIVE_SUBTAB]: 'vp_ss' });
```

### 2.2 Пастка спрацює на першому «слухняному» розробнику

Трасування ймовірного майбутнього збою: розробник (або ШІ-агент) відкриває `StorageSchema`,
бачить `Record<string, string>` і пише «за типом» — наприклад, щоб запам'ятовувати активну
підвкладку **окремо для кожної вкладки**:

```
1. Новий код: SYH_STORAGE.set({ 'syh:popup:active_subtab': { 'tab-telegram': 'vp_ss' } });
2. tsc: помилки немає (тип навіть збігається з декларацією!).
3. Попап перезапускається -> restoreActiveSubtabUI(result).
4. readStoredValue<string>(...) повертає ОБ'ЄКТ { 'tab-telegram': 'vp_ss' },
   хоча статично він типізований як string.
5. SHEET_IDS.includes(activeSubtabVal) -> includes() отримує об'єкт
   -> строге порівняння з рядками -> завжди false.
6. Спрацьовує ранній `return`. Виключення НЕ кидається, у консолі ТИХО.
7. Симптом для користувача: попап мовчки відкривається на дефолтній підвкладці,
   вибір аркуша «не запам'ятовується». Жодної помилки, яку можна загуглити.
```

Найгірше тут — **мовчазність**: `!SHEET_IDS.includes(...)` перетворює помилку типу на
беззвучний no-op. Дебаг такого — це години, бо `tsc`, лінтер і тести залишаться зеленими.

### 2.3 Другий вектор: неконсистентність із легасі-міграцією

`migrateKey('tg_active_subtab') -> 'syh:popup:active_subtab'` (`modules/storage_keys.ts:158`).
Старий ключ `tg_active_subtab` історично зберігав рядок. Тобто після міграції в канонічний
ключ гарантовано потрапляє **рядок**, що остаточно суперечить декларації `Record<string, string>`.

## 3.2 Ризики міграції

1. **Ризик низький, але не нульовий.** Якщо десь у коді значення вже приводиться до
   `Record<string, string>` через `as`, після звуження типу з'явиться помилка `tsc` —
   її треба буде розв'язати, а не заглушити новим `as`.
2. **Дані в сховищі користувачів не змінюються.** Правка суто на рівні типів; жодної
   міграції storage не потрібно, `STORAGE_SCHEMA_VERSION` піднімати **не треба**.
3. **Прибирання `[key: string]: any` — окрема, значно ризикованіша задача.** Воно
   ймовірно оголить десятки місць із динамічними ключами (`syh:popup:sheet:*`,
   `syh:popup:collected:*`, `syh:studio:state:*`). Змішувати її з цією однорядковою правкою
   категорично не варто.
4. **Тести не мають постраждати:** наявні тести вже передають рядок, тож звуження типу
   лише підтвердить їхню правоту.

## 6. Побічні спостереження (наприклад, загальний стан type-check у проєкті)

1. **Type-check зелений, але частково «сліпий».** `npx tsc --noEmit` дає 0 помилок, проте
   індексна сигнатура `[key: string]: any` у `StorageSchema` вимикає перевірку для **всіх**
   ключів сховища. Це системний ризик: описаний тут баг — лише один із можливих проявів.
   Рекомендую окрему задачу «звузити `StorageSchema`».
2. **`readStoredValue<T>` — непровірене приведення типу.** Дженерик задає очікуваний тип, але
   рантайм-валідації немає, тож будь-яка розбіжність зі схемою проявиться не помилкою, а
   мовчазною відмовою (як у трасуванні в п. 2.2). Кандидат на легкі type-guard'и.
3. **Патерн «тихого return» повторюваний.** Конструкція `if (!x || !LIST.includes(x)) return;`
   зустрічається у відновлювачах стану попапа. Вона надійна проти сміття в сховищі, але
   маскує помилки програміста. Варто хоча б `console.warn` у dev-збірці.
4. **Стан проєкту після рефакторингу цієї сесії:** тести 1398/1398 (було 1311 + 87 нових
   характеристичних), `tsc` — 0 помилок, `fallow dead-code` — 1 преіснуюча знахідка
   (`tests/debug_dialog2.mjs`), lint — 3 преіснуючі попередження у незмінених файлах.
5. **Health score:** 78.1 (B) → 78.4 (B); `background/service-worker.ts` скоротився з 232 до
