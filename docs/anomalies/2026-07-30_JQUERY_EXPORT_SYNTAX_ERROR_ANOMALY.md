# 📌 Аномалія: Синтаксична помилка jQuery (Unexpected token 'export') після рефакторингу на TypeScript та Vite

**Дата фіксації:** 2026-07-30  
**Середовище:** Google Chrome / Chrome Extension (Manifest V3)  
**Компонент:** Content Scripts (`lib/jquery-3.7.1.js`, `lib/chart.js`, `main.ts`)  
**Статус:** Вирішено (Виправлено конфігурацію manifest.json та спосіб імпорту бібліотек).

---

## 1. 🚨 Опис проблеми та діагностика (Root Cause)

Після переходу проєкту на **TypeScript** та збирач **Vite** з плагіном `@crxjs/vite-plugin` (для Manifest V3), під час завантаження розширення на сторінці `https://streamyard.com/broadcasts` виникла синтаксична помилка:
```text
Uncaught SyntaxError: Unexpected token 'export'
assets/jquery-3.7.1.js-T69IKIHc.js:13 (анонімна функція)
```

Через це jQuery не завантажувався, і глобальні змінні `window.$` та `window.jQuery` залишалися `undefined`, що ламало роботу всієї логіки розширення (`main.ts`).

### Причина виникнення аномалії:
1. **Змішаний режим завантаження в `manifest.json`**:
   У початковому `manifest.json` бібліотеки та скрипти були перелічені окремими файлами:
   ```json
     "content_scripts": [
       {
         "matches": ["https://streamyard.com/*"],
         "js": [
           "lib/jquery-3.7.1.js",
           "lib/chart.js",
           "main.ts"
         ]
       }
     ]
   ```
2. **Особливості збірки Vite**:
   Оскільки ці файли були вказані як окремі точки входу в контентові скрипти, Vite збирав кожен з них як окремий модуль. Для `lib/jquery-3.7.1.js` збирач згенерував ES-модуль, який закінчувався інструкцією `export default Wr();`.
3. **Обмеження Chrome на запуск Content Scripts**:
   Chrome Extensions у Manifest V3 за замовчуванням завантажують файли з масиву `content_scripts.js` як класичні скрипти (не як ES-модулі), де ключове слово `export` є недопустимим. 
4. **Помилка згенерованого завантажувача CRXJS**:
   Плагін `@crxjs/vite-plugin` створив завантажувач (`main.ts-loader.js`) лише для `main.ts`, але файли `jquery-3.7.1.js` та `chart.js` вставив у `dist/manifest.json` напряму без завантажувачів. Через це Chrome намагався виконати скомпільований ES-модуль jQuery як звичайний скрипт, що призвело до `SyntaxError`.

---

## 2. 🛠️ Рішення (Solution)

Проблему було вирішено шляхом інтеграції бібліотек у єдину модульну структуру збірки Vite.

### Крок 1. Очищення `manifest.json`
Ми прибрали пряму реєстрацію сторонніх бібліотек з контентових скриптів маніфесту. Тепер там зареєстровано виключно головний скрипт `main.ts`:
```json
  "content_scripts": [
    {
      "matches": ["https://streamyard.com/*"],
      "css": ["styles.css"],
      "js": [
        "main.ts"
      ]
    }
  ]
```

### Крок 2. Перенесення jQuery в імпорти модулів (`main.ts`)
Замість глобального завантаження через маніфест, мы імпортували jQuery на самому початку `main.ts` як залежність для побічних ефектів (side-effects import):
```typescript
import './lib/jquery-3.7.1.js';
```
* **Чому це працює:** Оскільки `main.ts` завантажується через згенерований плагіном CRXJS завантажувач (який використовує динамічний `import()`), весь контекст виконання стає контекстом ES-модуля. У цьому контексті інструкції `export` є повністю валідними. jQuery завантажується як частина дерева залежностей `main.ts` і виконується.

* **Важливе доопрацювання UMD-обгортки jQuery:** 
  При роботі як модуль (CommonJS/ES) у збірці Vite, UMD-обгортка jQuery викликає фабрику з аргументом `noGlobal = true`:
  ```javascript
  module.exports = global.document ? factory( global, true ) : ...
  ```
  Через це jQuery пропускав присвоєння глобальним змінним:
  ```javascript
  if ( typeof noGlobal === "undefined" ) {
      window.jQuery = window.$ = jQuery;
  }
  ```
  Для усунення цієї поведінки ми змінили умову в обгортці [lib/jquery-3.7.1.js](file:///d:/Chrome%20Extension/%D0%92%D1%80%D0%B5%D0%BC%D1%8F%20%D0%BF%D0%B5%D1%80%D0%B5%D0%BC%D0%B5%D0%BD.%20Chrome%20Extension/streamyars-copy-buttons%20%28added%20checkbox%29%200.6-2026.01.11/lib/jquery-3.7.1.js) на `if ( typeof noGlobal === "undefined" || true )`, що гарантує обов'язкове оголошення `window.$` та `window.jQuery` у пісочниці розширення незалежно від контексту запуску.

### Крок 3. Додавання `type="module"` у попап (`popup.html`)
Аналогічна проблема виникала у попапі, де тег `<script src="../lib/jquery-3.7.1.js">` викликав попередження збирача:
`in "/popup/popup.html" can't be bundled without type="module" attribute`
Додавання атрибута `type="module"` вирішило проблему збірки та дозволило Vite коректно скомпілювати та переписати шляхи до скриптів у попапі.

---

## 3. 🛡️ Висновки для архітектора та майбутніх розробок

1. **Правило імпорту сторонніх бібліотек**: 
   Ніколи не додавайте великі JS-бібліотеки (jQuery, Chart.js тощо) окремими елементами в масив `content_scripts.js` маніфесту, якщо проєкт збирається за допомогою Vite. Завжди імпортуйте їх безпосередньо у коді скриптів (як `import './lib/...'` або через npm-пакети).
2. **Роль динамічного завантаження**: 
   Для бібліотек, які потрібні на вимогу (як-от `chart.js` для побудови графіків аналітики), краще залишати динамічне завантаження через `fetch` + `eval` або динамічний ES `import()`. Це зменшує час первинного завантаження сторінки розширення.
