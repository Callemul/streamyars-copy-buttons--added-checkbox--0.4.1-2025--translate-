# 📌 Аномалії: Викривлення підсвічування тригерів ("12") та критична помилка "Extension context invalidated"

**Дата фіксації:** 2026-07-30  
**Середовище:** Google Chrome / Chrome Extension (Manifest V3)  
**Компоненти:** Помічник коментарів (`modules/comment_assistant.ts`), Адаптер локалізації (`modules/i18n.ts`), Конфігурація (`modules/config.ts`), Завантажувач відео (`modules/video_copier.ts`)  
**Статус:** Вирішено (Виправлено логіку колбеку заміни регулярного виразу та додано try-catch захист навколо chrome.i18n API).

---

## 1. 🚨 Аномалія 1: Викривлення HTML-підсвічування тригерів (поява індексу "12" та дублювання тексту)

### Опис проблеми та діагностика (Root Cause)
При знаходженні тригерних слів (наприклад, "вопрос") розширення замінювало слово на HTML-тег `<mark class="syh-trigger-highlight">`. Проте замість підсвіченого слова вставлялося число зсуву (наприклад, `<mark>12</mark>` або `<mark>0</mark>`), а оригінальний текст коментаря дублювався.

**Причина виникнення:**
У JavaScript метод `.replace(rx, (match, p1, p2, p3) => { ... })` передає аргументи колбеку залежно від кількості груп захоплення в регулярному виразі.
1. **Unicode lookbehind регулярний вираз** (основний) має **1 групу захоплення**: `(вопрос)`.
   Тому аргумент `p1` є знайденим словом (наприклад, `"Вопрос"`), а `p2` стає **числовим індексом (offset)** початку збігу в тексті (наприклад, `12`).
2. **Фолбек регулярний вираз** (запасний) має **3 групи захоплення**: `(^|[^a-zA-Z0-9...])(вопрос)($|[^a-zA-Z0-9...])`.
   Тому `p1`, `p2`, `p3` є рядками тексту навколо слова, а зсув передається як 5-й аргумент.

Оскільки код розраховував виключно на 3 групи (`const targetWord = p2 || p1 || match`), при використанні основного регулярного виразу змінна `targetWord` отримувала значення `p2` (число `12`), що є правдивим (`truthy`), і повертався дубльований рядок `${p1}${replacement}${p3}` (де `p3` ставав повним оригінальним текстом).

### Рішення (Solution)
Впроваджено тип-чек перевірку для аргументу `p2` у файлі [comment_assistant.ts](file:///d:/Chrome%20Extension/%D0%92%D1%80%D0%B5%D0%BC%D1%8F%20%D0%BF%D0%B5%D1%80%D0%B5%D0%BC%D0%B5%D0%BD.%20Chrome%20Extension/streamyars-copy-buttons%20%28added%20checkbox%29%200.6-2026.01.11/modules/comment_assistant.ts):
```typescript
const isFallback = typeof p2 === 'string';
const targetWord = isFallback ? p2 : (p1 || match);
```
Якщо `p2` — рядок, використовуємо 3-груповий фолбек-патерн. Якщо ні (це число-offset) — використовуємо lookbehind-патерн з 1 групою.

### Зміна поведінки (На вимогу користувача)
Видалено умову `if (isChecked)` з методу `processComment`, яка очищала підсвічування тригерних слів, коли коментар позначався як "Опрацьований". Тепер тригерні слова залишаються підсвіченими завжди, незалежно від стану чекбокса "Опрацьовано" (встановленого як вручну, так і автоматично по ПКМ).

## 2. 🚨 Аномалія 2: Консольний краш розширення "Uncaught Error: Extension context invalidated"

### Опис проблеми та діагностика (Root Cause)
При перезавантаженні або оновленні розширення (наприклад, після виконання команди `npm run build`), на раніше відкритих вкладках StreamYard старий контентний скрипт продовжував працювати. При спробі звернення до локалізації через API Chrome:
```typescript
chrome.i18n.getMessage('stayInStudio')
```
браузер викидав фатальну помилку `Extension context invalidated`, що повністю зупиняло виконання скриптів розширення на сторінці.

### Рішення (Solution)
Було захищено всі виклики `chrome.i18n.getMessage` за допомогою блоків `try-catch` у файлах:
- [i18n.ts](file:///d:/Chrome%20Extension/%D0%92%D1%80%D0%B5%D0%BC%D1%8F%20%D0%BF%D0%B5%D1%80%D0%B5%D0%BC%D0%B5%D0%BD.%20Chrome%20Extension/streamyars-copy-buttons%20%28added%20checkbox%29%200.6-2026.01.11/modules/i18n.ts) — додано обробку помилки всередині адаптера `SYH_I18N.getMessage`.
- [config.ts](file:///d:/Chrome%20Extension/%D0%92%D1%80%D0%B5%D0%BC%D1%8F%20%D0%BF%D0%B5%D1%80%D0%B5%D0%BC%D0%B5%D0%BD.%20Chrome%20Extension/streamyars-copy-buttons%20%28added%20checkbox%29%200.6-2026.01.11/modules/config.ts) — додано try-catch у геттер `timerOffTextResult`.
- [video_copier.ts](file:///d:/Chrome%20Extension/%D0%92%D1%80%D0%B5%D0%BC%D1%8F%20%D0%BF%D0%B5%D1%80%D0%B5%D0%BC%D0%B5%D0%BD.%20Chrome%20Extension/streamyars-copy-buttons%20%28added%20checkbox%29%200.6-2026.01.11/modules/video_copier.ts) — додано try-catch для `downloadText`.

Якщо контекст розширення втрачено (invalidated), помилки більше не зупиняють виконання, а скрипти продовжують роботу, використовуючи рядки-заглушки за замовчуванням (fallback).

## 🛡️ Висновки для розробників
1. **Колбеки замін RegExp**: При роботі з методом `.replace(regex, callback)` у JavaScript завжди враховуйте кількість груп захоплення у виразі. Якщо регулярний вираз може динамічно змінюватися (наприклад, через фолбеки lookbehind), обов'язково перевіряйте типи параметрів колбеку перед використанням.
2. **Вразливість chrome.* API при оновленні**: Будь-яке розширення має бути стійким до оновлень у фоні. Усі прямі звернення до `chrome.storage`, `chrome.i18n`, `chrome.runtime` у довгоживучих MutationObserver або інтервалах повинні обгортатися в `try-catch` або перевіряти доступність контексту, щоб уникнути передчасного падіння скриптів на відкритих сторінках користувача.
