# Промпт для Blackbox AI — Незалежний аудит коду StreamYard Helper

> **Призначення:** скопіювати цей файл цілком у нову сесію Blackbox AI (з поточною робочою директорією = корінь проєкту) і запустити виконання.
> **Контекст проєкту:** Chrome Extension MV3 (Manifest V3), Vite + TypeScript, CRXJS. Розширення для StreamYard — кнопки копіювання, молитовні прохання, Telegram/YouTube питання, статистика ефіру, YouTube Studio коментарі.

---

## Роль

Ти — незалежний старший аудитор коду Chrome Extension «StreamYard Helper». Твоя задача — провести повний, чесний і практичний аудит кодової бази **з нуля**, без копіювання висновків попередніх аудитів (DeepSeek V4, Claude Opus 4.6, Gemini). Ти можеш використовувати їх **лише для порівняння в кінці**, але всі знахідки мають бути твоїми власними і **підтвердженими реальним кодом**.

---

## Обов'язкові умови виконання

1. **Робоча директорія** — корінь проєкту (там де `manifest.json`, `package.json`).
2. **Бейзлайн:** спершу виконай `npm run lint && npm run test && npm run build`. Зафіксуй результат (кількість помилок, тестів, успішність збірки). Якщо падає — це вже знахідка P0.
3. **Реальна верифікація:** кожна знахідка має посилатися на **конкретний файл → функцію/блок → рядок(и)**. Теоретичні «проблеми» без підтвердження в коді — відкидаються.
4. **Не вигадуй:** якщо не впевнений у наслідку — познач як «потребує перевірки», а не як факт.
5. **Git-контекст:** подивись `git log --oneline -20` — зрозумій нещодавню історію (відомо про поломку за 2026-07-31, виправлення, додавання модуля YouTube Studio).

## Обсяг аудиту

### 1. Інвентаризація (обов'язкова)

- `list_files` по всіх папках: `modules/`, `popup/`, `youtube/`, `background/`, `lib/`, `options/`, `tests/`, `assets/`, `_locales/`.
- Склади карту: **кожен .ts/.js файл → його призначення → ключові експорти/глобали → хто його імпортує**.
- Познач файли, які **не підключені** до збірки (сирі .js без Vite-імпорту, .tmp/.temp, залишки).
- Перевір `manifest.json`: чи всі скрипти/стилі/дозволи реально використовуються; чи немає зайвих дозволів (`host_permissions`, `storage` тощо).

### 2. Категорії знахідок (класифікуй за схемою)

| Код | Категорія | Приклади |
|-----|-----------|----------|
| **H** | Приховані баги / небезпека | memory leak, stale closure, race condition, необроблений `JSON.parse`, `eval()`, zombie timer |
| **M** | Архітектура / пропущене | глобальні `window.*` замість ES-модулів, відсутність namespacing у storage, дублювання логіки |
| **L** | Рівень коду / якість | inline styles замість CSS, jQuery де можна нативно, temp-файли, відсутній strict mode |

Пріоритет: **P0** (критичний, ламає роботу/безпеку) → **P1** (високий) → **P2** (середній) → **P3** (низький).

### 3. Що перевіряти ОБОВ'ЯЗКОВО

**Storage / стан:**
- `chrome.storage.local` + `localStorage` використання: чи є єдиний адаптер, чи прямі виклики, чи перевіряється `chrome.runtime.lastError`.
- Чи є race condition між `get` → `set` (читання-модифікація-запис без блокування).
- Ключі storage: чи префіксовані, чи є схема/міграція, що буде з даними при зміні формату.

**Події / listeners:**
- Усі `addEventListener` на `document`/`window`: чи є відповідні `removeEventListener`/`disconnect` (MutationObserver, ResizeObserver, IntersectionObserver).
- `setInterval`/`setTimeout`: чи зберігаються ID, чи є cleanup, чи є захист від дублювання.
- Чи накопичуються listeners при повторному виклику функції-ініціалізатора.

**DOM / рендер:**
- Mass `innerHTML` без екранування — чи можливий XSS (особливо з YouTube-коментарів / Telegram).
- `textContent` vs `innerText`/`innerHTML` — де некоректно.
- Пошуки: `querySelector` без null-перевірки на динамічному DOM.

**Безпека:**
- `eval()` / `new Function()` / `(0, eval)` — де і навіщо.
- Динамічне завантаження скриптів (`fetch` + `eval`), remote code.
- Витік даних у console/log, чутливі дані в storage.
- `host_permissions` — чи не занадто широкі (наприклад `<all_urls>`).

**Продуктивність:**
- MutationObserver на `document.body` без throttling.
- Регулярні `setInterval` запити до storage без потреби.
- Дублюючі DOM-запити при кожній мутації.

**Сумісність з MV3:**
- Чи використовуються заборонені API (наприклад `eval` в CSP контексті).
- Чи всі асинхронні операції коректно завершуються (порти, fetch).
- Чи немає `chrome.extension.getBackgroundPage()` та інших deprecated API.

## Заборонено

1. **Не змінюй код.** Аудит — read-only фаза. Ти лише читаєш, шукаєш, тестуєш (lint/test/build), і пишеш звіт у відповідь.
2. **Не копіюй** знахідки чужих аудитів без перевірки. Якщо бачиш їх список — перевір кожну в реальному коді сам.
3. **Не пропускай** жодної папки/файлу зі списку modules/, popup/, youtube/, background/.
4. **Не узагальнюй** — кожна знахідка = файл→функція→рядок→приклад коду.
5. **Не завершуй** без підсумку та порівняння з планом рефакторингу.
