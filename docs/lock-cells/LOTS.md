# ЛОТ 1 — Ядро стану фіксацій

**Модель:** Claude Sonnet 5
**Залежить від:** ЛОТ 0
**Гілка:** `feat/lock-cells-1-store`

```text
[СПІЛЬНІ ПРАВИЛА]

РОЛЬ
Фронтенд-розробник. Робиш «двигун» фіксацій — без жодного UI.

КОНТЕКСТ
Читай docs/lock-cells/PLAN.md (розділ 3) і docs/lock-cells/SPEC.md.
Формат ключа і формат зберігання — ті, що затверджені у SPEC.md.

ЗАВДАННЯ
1. Створи стор фіксацій (у стилі решти сторів проєкту) з API:
   - isLocked(cellKey): boolean
   - setLocked(cellKeys: CellKey[], value: boolean): void   // одна транзакція
   - toggle(cellKey): void
   - lockScope(scope, value)  де scope = {type:'all'|'day'|'teacher'|'column',
     id?}, працює ТІЛЬКИ по видимих (переданих) клітинках
   - stats(): { total, locked }  та statsFor(scope): { total, locked }
   - scopeState(scope): 'none' | 'partial' | 'all'    // для трьохстанних заголовків
   - subscribe(cellKey, cb) — точкова підписка, щоб перемалювати одну клітинку
   - replaceAll(cellKeys) / serialize() / hydrate(raw)
2. Усередині — Set<CellKey>. Лічильники по днях і вчителях тримай у
   похідному кеші, який інвалідується транзакцією, а не перераховується
   на кожен виклик.
3. Збереження: дебаунс 400 мс, оптимістичне оновлення, відкат стану при
   помилці мережі + подія для тоста (сам тост — ЛОТ 5).
4. Гідрація і міграція: version, апгрейд старого формату, відкидання
   ключів на неіснуючих вчителів/дні/уроки; повертай кількість відкинутих.
5. Транзакція: усі зміни одного виклику — одна подія для підписників і
   одна майбутня одиниця undo (сам undo — ЛОТ 5, але API має віддавати
   опис зміни: { before: CellKey[], after: CellKey[], label }).

ОБМЕЖЕННЯ
- Жодного React/DOM у сторі. Чиста логіка + підписки.
- Ніякого UI, ніяких кнопок. Це закриють інші лоти.

ТЕСТИ (обов'язково)
- toggle, setLocked масивом, ідемпотентність повторного setLocked
- lockScope по дню/вчителю/колонці рахує тільки видимі клітинки
- scopeState віддає partial коректно
- міграція: битий формат, чужі ключі, порожньо, стара версія
- 20 000 ключів: setLocked на 5 000 клітинок < 20 мс

DEFINITION OF DONE
- Усі тести зелені, лінт і типи чисті.
- У підсумку — приклад використання API на 10 рядків.
```

# ЛОТ 2 — Візуальна мова зафіксованої клітинки

**Модель:** Claude Haiku 4.5
**Залежить від:** ЛОТ 0
**Гілка:** `feat/lock-cells-2-visual`

```text
[СПІЛЬНІ ПРАВИЛА]

РОЛЬ
Верстальник дизайн-системи. Тільки стилі, жодної логіки.

ЗАВДАННЯ
Зробити візуальні стани клітинки й легенду, використовуючи токени наявної
дизайн-системи (знайди їх, нових кольорів не вигадуй).

Стани:
1. .cell--locked — легкий тінт + діагональне штрихування 45° (крок 6px,
   товщина 1px) + іконка замка 10px у правому верхньому куті, 60% прозорості.
2. .cell--locked.cell--empty — штрихування без тінту + бліде «—» по центру,
   title «Залишиться порожньою».
3. .cell--lock-preview — стан під час протяжки (яскравіша рамка, без
   штрихування), і .cell--unlock-preview — те саме для зняття.

- світла і темна тема через наявні токени;
- контраст рамки/штрихування до фону ≥ 3:1;

- штрихування — CSS-градієнтом, не картинкою.

Легенда: маленький компонент під сіткою, згорнутий за замовчуванням,
пояснює три стани (звичайна / зафіксована / зафіксована порожня).

Демо: додай сторінку/сторі з сіткою 6×8, де є всі стани поруч, щоб
дизайнер міг подивитись без запуску всієї програми.

DEFINITION OF DONE
- Усі 6 станів видно на демо, у світлій і темній темі.
- У жодному стані сенс не передається лише кольором.
- Логіки (JS) не додано.
```

# ЛОТ 4 — Режим фіксації і малювання мишкою

**Модель:** Claude Opus 5
**Залежить від:** ЛОТ 1, ЛОТ 2
**Гілка:** `feat/lock-cells-4-paint`
**Найскладніший лот. Не давати молодшій моделі.**

```text
[СПІЛЬНІ ПРАВИЛА]

РОЛЬ
Старший фронтенд-розробник, спеціалізація — складна взаємодія з покажчиком
і продуктивність DOM.

ЗАВДАННЯ
Зробити режим фіксації з малюванням по клітинках.

A. Тумблер режиму
   - кнопка-тумблер «🔒 Режим фіксації» в панелі, гаряча клавіша L;
   - поки увімкнено: сітка в класі .grid--lock-mode, статус-смужка зверху
     («Режим фіксації: клікайте або протягуйте по клітинках · Esc — вийти»),
     звичайне редагування/перетягування уроків вимкнене;
   - Esc виходить з режиму (якщо не йде протяжка).
   - Поза режимом: Alt+клік по клітинці фіксує/знімає — працює завжди.

B. Малювання (Pointer Events, не mouse!)
   - pointerdown на клітинці: paintValue = !isLocked(клітинка); ставимо
     setPointerCapture; клітинка одразу отримує прев'ю-клас;
   - рух: усі клітинки під покажчиком отримують paintValue; повторний
     прохід нічого не змінює; для тач і для віртуалізованої сітки
     hit-test через document.elementFromPoint, а не через збережені вузли;
   - pointerup: комміт однією транзакцією стору з міткою
     «Зафіксовано N клітинок» / «Знято фіксацію з N клітинок»;
   - простий клік без руху = перемикання однієї клітинки (той самий шлях);
   - Esc під час протяжки: скасувати ВСЮ поточну протяжку, повернути як було;
   - pointercancel / втрата фокуса вікна = те саме, що Esc.

C. Модифікатори
   - Alt під час протяжки — примусово фіксувати;
   - Ctrl/Cmd — примусово знімати;
   - Shift на pointerdown — прямокутник від якоря до поточної клітинки,
     живе прев'ю, комміт на відпусканні. Якір = остання клітинка, якої
     торкались (або та, на якій натиснули Shift).

D. Автоскрол
   - якщо покажчик ближче 40px до краю контейнера — прокрутка з
     прискоренням (від 4 до 24 px/кадр), поки не відпустять.

E. Живий зворотний зв'язок
   - статус-смужка під час протяжки: «Виділено 23 · відпустіть, щоб
     зафіксувати»;
   - жодного ререндеру сітки під час руху: тільки classList на зачеплених
     клітинках, батчинг у requestAnimationFrame.

ПРОДУКТИВНІСТЬ (перевіряти, не вірити на слово)
- 20 000 клітинок: кадр протяжки < 8 мс (заміряй, наведи цифри в підсумку);
- нуль forced reflow всередині циклу руху (жодних offsetWidth/getBoundingClientRect
  на кожній клітинці — розміри кешуй один раз на початку протяжки).

ДРІБНИЦІ, ЯКІ ЛАМАЮТЬ ВРАЖЕННЯ (закрити всі)
- текст не виділяється під час протяжки (user-select: none + preventDefault);
- на тачі сторінка не скролиться під пальцем (touch-action: none на сітці
  лише в режимі фіксації);
- права кнопка миші й контекстне меню не починають протяжку;
- відпускання поза сіткою або поза вікном коректно завершує протяжку;
- вихід з вкладки «Проєкти» під час протяжки нічого не ламає.

DEFINITION OF DONE
- Клік, протяжка, прямокутник, зняття протяжкою, Esc, автоскрол —
  усе працює мишею і пальцем.
- Одна протяжка = одна одиниця undo.
- Цифри продуктивності наведені в підсумку PR.
- Написані e2e-тести на: протяжку по 5 клітинках, протяжку зі зняттям,
  Shift-прямокутник, Esc під час протяжки.
```

# ЛОТ 5 — Undo/Redo і сповіщення

**Модель:** Claude Sonnet 5
**Залежить від:** ЛОТ 3, ЛОТ 4
**Гілка:** `feat/lock-cells-5-undo`

```text
[СПІЛЬНІ ПРАВИЛА]

РОЛЬ
Фронтенд-розробник.

ЗАВДАННЯ
1. Стек команд для фіксацій: до 50 кроків, у пам'яті сесії.
   Одна масова дія = один крок. Одна протяжка = один крок.
   Ctrl+Z / Ctrl+Shift+Z (і Cmd на macOS). Якщо в проєкті вже є
   глобальний undo — вбудуйся в нього, не роби другий.
2. Тост після кожної масової дії й після протяжки:
   «Зафіксовано 30 клітинок» + кнопка «Скасувати» (живе 8 секунд).

5. Оголошення для скрінрідера (aria-live="polite") на кожну масову дію.
```

# ЛОТ 6 — Інтеграція з перегенерацією

**Модель:** Claude Opus 5
**Залежить від:** ЛОТ 1 (і висновків ЛОТу 0, пункт про солвер)
**Гілка:** `feat/lock-cells-6-regenerate`

```text
[СПІЛЬНІ ПРАВИЛА]

РОЛЬ
Fullstack-розробник. Найризикованіша частина: зафіксована клітинка мусить
лишитись недоторканою, інакше вся фіча — обман.

ЗАВДАННЯ
1. Передати фіксації в перегенерацію ЖОРСТКИМ обмеженням (не вагою,
   не «побажанням»). Формат тіла запиту узгодь із тим, що описано в
   docs/lock-cells/SPEC.md, пункт 4. Якщо солвер зараз не вміє жорсткі
   обмеження — спочатку напиши в PR, що саме треба додати, і зроби
   мінімальну підтримку; не імітуй фіксацію фільтрацією результату.
2. Прев'ю перед стартом: діалог «Буде перегенеровано 258 клітинок.
   42 зафіксовані залишаться без змін.» + чекбокс «Більше не показувати».
   Якщо зафіксовано 0 — діалог не показувати взагалі.
3. Чип біля кнопки «Перегенерувати»: «Зафіксовано 42 з 300».
4. Перевірка після генерації: порівняти всі зафіксовані клітинки до/після.
   Розбіжність = помилка: показати користувачу зрозуміле повідомлення,
   залогувати подію телеметрії lock_violation з деталями.
5. Конфлікт обмежень (солвер не може виконати): НЕ скидати фіксації
   самовільно. Показати список конфліктних клітинок, підсвітити їх
   у сітці, дати дії «Показати на сітці» і «Зняти конфліктні фіксації
   та повторити».
6. Поки генерація йде — панель фіксації і сітка в read-only з підказкою.

ТЕСТИ
- інтеграційний: 10 зафіксованих клітинок, перегенерація, усі 10 не змінились;
- конфлікт: свідомо суперечливі фіксації → показано список, нічого не
  скинуто мовчки;
- 0 фіксацій → поведінка перегенерації така сама, як була до фічі
  (перевірити, що нічого не зламали).

DEFINITION OF DONE
- Зафіксована клітинка не змінюється після перегенерації — доведено тестом.
- Жоден шлях коду не знімає фіксації без явної дії користувача.
- У підсумку PR чесно написано, чи солвер підтримує обмеження нативно,
  чи це обхідний шлях, і які в нього межі.
```
