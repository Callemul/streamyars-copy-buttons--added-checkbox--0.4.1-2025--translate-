# 🏗️ План рефакторингу: Фіксація синхронізації StreamYard

## Контекст проблеми

Під час розробки модуля YouTube Studio відбувалось часте перезавантаження розширення.
У zombie context (`chrome.runtime.id = undefined`) модуль `storage.ts` тихо перемикався
на `localStorage` *сайту streamyard.com*. Попап завжди читає з `chrome.storage.local` напряму —
і не бачив зібраних молитов, банерів. **Виявлена причина підтверджена кодом.**

---

## ⚠️ Важливо до початку

> [!WARNING]
> Етап 1 виправляє живий баг. Після нього **треба протестувати вручну**: відкрити StreamYard,
> перезавантажити розширення через `chrome://extensions`, переконатись що банери/молитви
> не зникають і синхронізуються з попапом.

> [!IMPORTANT]
> `stats_tracker.ts` має окреме навмисне звернення до `localStorage` сайту
> (читає бренд зі стану StreamYard). Це **не баг** — це фіча. Не чіпаємо.

## Перевірка після виконання

### Автоматично (CI):
```bash
npm run lint
npm run test     # включаючи новий storage.test.js
npm run build
```

### Вручну (браузер):
1. Відкрити streamyard.com з активною трансляцією
2. Зібрати кілька молитов/питань через контент-скрипт
3. Відкрити попап → переконатись що молитви видно у вкладці "Молитви"
4. Зробити hard reload розширення в `chrome://extensions`
5. Повернутись на StreamYard → попап має **все ще** показувати молитви з `chrome.storage.local`
6. В DevTools консолі НЕ має бути `Fallback to localStorage`
