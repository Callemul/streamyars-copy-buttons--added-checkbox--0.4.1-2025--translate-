## 1. StreamYard — дії над коментарем (T7, найризикованіше)

Відкрити `https://streamyard.com/…` → студія з живими коментарями (вкладка
«Коментарі»), консоль F12 відкрита — стежити, чи немає помилок.

### 1.1. Кнопка 🙏 — три різні результати від трьох кнопок миші

Це головна відмінність StreamYard від YouTube: результат залежить від того,
**якою кнопкою миші** натиснули. Після T7 це описано в реєстрі (`mouseButtons`),
а не зашито в обробнику — тобто саме тут найлегше було щось загубити.

- [ ] **ЛКМ** по 🙏 → у буфер лягає варіант `🙏🙏🙏`; з'являється банер копіювання
- [ ] **Коліщатко (середня кнопка)** по 🙏 → у буфер лягає варіант `🙏❤️🙏`
- [ ] Коліщатко **не** відкриває нову вкладку і не вмикає автоскрол сторінки
- [ ] **ПКМ** по 🙏 → у буфер лягає варіант `❤️❤️❤️`
- [ ] ПКМ по 🙏 **не** відкриває контекстне меню браузера
- [ ] Після кожного з трьох кліків запис з'являється в базі молитов (попап →
      вкладка «Молитовні»), і саме один раз, не тричі

### 1.2. Решта кнопок панелі

- [ ] **📄** (копіювати коментар) → у буфері текст коментаря, кнопка коротко «спалахує»
- [ ] **❓** (копіювати автора + коментар) → у буфері автор і текст, запис
      потрапляє у список питань
- [ ] Порядок кнопок у панелі: 📄 · ❓ · 🙏 · чекбокс — зліва направо, без пропусків
- [ ] Іконки й підказки (`title` при наведенні) ті самі, що були до хвилі

### 1.3. Чекбокс «опрацьовано»

- [ ] Клік по чекбоксу відмічає коментар
- [ ] **ПКМ по тілу коментаря** також перемикає чекбокс (це історична поведінка)
- [ ] Стан чекбокса тримається **за текстом коментаря**: якщо StreamYard
      перемалював список, галочка лишилась на тому самому коментарі
- [ ] Стан чекбокса **не** переживає перезавантаження сторінки (він в оперативному
      `SYH_STATE`, а не в `chrome.storage`) — це очікувано, не баг

### 1.4. Auto-Heal і зірка платформи

- [ ] Натиснути ⭐ на коментарі → зняти ⭐ → панель наших кнопок повернулась
      на місце й **кнопки працюють** (натиснути 📄 і переконатись, що копіює)
- [ ] Перемкнутись на вкладку «Starred» і назад → кнопки на місці й робочі
- [ ] Прогорнути список коментарів угору-вниз кілька разів (StreamYard
      перемальовує картки) → у нових карток кнопки з'явились і працюють
- [ ] На картці, яку щойно позначили ❓/🙏, атрибут `data-syh-just-added`
      тримається ~2 с і зникає (перевірити в Elements)

### 1.5. Запобіжник цієї хвилі — панель без прив'язки

Це те, що ловить новий тест `tests/streamyard_panel_binding_invariant.test.js`.
У браузері симптом виглядав би так: **кнопки на місці, натискаєш — нічого**.

- [ ] Пройти пунктами 1.1–1.4 і переконатись, що **немає жодної картки**, де
      кнопки намальовані, але не реагують
- [ ] В Elements у контейнера `.syh-custom-buttons-comment` кожної картки з
      кнопками є атрибут `data-syh-events-bound="true"`

### 1.6. Перезавантаження розширення при вже відкритій сторінці

Класичне джерело `Extension context invalidated`.

- [ ] Відкрити студію з коментарями → `chrome://extensions` → 🔄 перезавантажити
      розширення → повернутись на вкладку студії **без перезавантаження сторінки**
- [ ] Натиснути 📄 на коментарі: або кнопка працює, або в консолі зрозуміле
      повідомлення — але **не** мовчазна тиша і не червона стіна помилок
- [ ] Після F5 сторінки все працює як звичайно

## 2. Попап — аркуші та поля (T8)

Відкрити попап (іконка розширення) → вкладка «Телеграм».

### 2.1. Поля зберігаються і відновлюються

Для КОЖНОГО аркуша (вкладки-канали внизу: ВП СШ, Опарін, Молчанов СШ,
Молчанов проповідь) — принаймні для двох різних:

- [ ] Заповнити «1. Старий список» → закрити попап → відкрити знову: текст на місці
- [ ] Заповнити «2. Номери ВІДПОВІДЕЙ» → закрити/відкрити: значення на місці
- [ ] Заповнити «3. Новий список» (ліва колонка, Telegram) → закрити/відкрити: на місці
- [ ] Натиснути «ОБРОБИТИ КОМЕНТАРІ» → у блоці «Результат» з'явився текст →
      закрити/відкрити: результат на місці
- [ ] Відредагувати текст прямо в блоці «Результат» (він contenteditable) →
      клацнути поза ним → закрити/відкрити: правка збереглась

### 2.2. Лічильники й похідний стан

- [ ] Лічильник біля «1. Старий список» перераховується при вводі
- [ ] Лічильники «Разом / Telegram / YouTube» у кроці 3 змінюються при вводі
- [ ] Панель статистики («Залишилось старих / Видалено / Нові / Разом») після
      обробки видима → закрити/відкрити попап: панель і далі видима з тими ж числами
- [ ] Розгорнути «🗑 Лог видаленого» → закрити/відкрити: лог розгорнутий,
      лічильник «(N)» той самий
- [ ] Згорнути «🧹 Лог чистки тексту» → закрити/відкрити: лишився згорнутим
- [ ] Перетягнути роздільник між колонками кроку 3 → закрити/відкрити:
      ширина колонок збереглась

### 2.3. Аркуші не змішуються

- [ ] Ввести РІЗНИЙ текст у «Старий список» на двох різних аркушах
- [ ] Перемкнутись між ними кілька разів — тексти не переплуталися
- [ ] Закрити/відкрити попап — обидва на своїх місцях

### 2.4. СТАРІ ДАНІ (найважливіше в T8)

T8 переписав те, ЯК читаються ключі сховища. Автотест на легасі-ключі є
(`tests/popup_sheet_fields.test.js`), але його треба підтвердити на живих даних.

- [ ] **Перед оновленням розширення** заповнити аркуш на попередній версії
      (старий список, номери відповідей, новий список, результат, розгорнути логи)
- [ ] Оновити розширення до цієї збірки (`chrome://extensions` → 🔄)
- [ ] Відкрити попап: **усі** значення на місці, логи в тому ж стані,
      лічильники ті самі, ширина колонок та сама
- [ ] Якщо щось зникло — **не продовжувати**, зафіксувати, яке саме поле

### 2.5. Очищення

- [ ] Кнопка 🗑 «Очистити» біля «ОБРОБИТИ КОМЕНТАРІ» питає підтвердження
- [ ] Після підтвердження поля аркуша порожні, інші аркуші не постраждали
- [ ] Кнопка 🗑 «Очистити зібрані» в колонці YouTube Studio чистить лише її
