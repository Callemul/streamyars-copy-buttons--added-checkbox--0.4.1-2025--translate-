# Інструкція для ШІ та розробників (Developer & AI Guidelines)

## Правила парсингу та обробки списків питань / молитов z Telegram

### 1. Початкова очистка скопійованого тексту (`cleanTelegramHeaders`)
- При копіюванні довгих повідомлень або декількох повідомлень з Telegram до тексту додаються службові заголовки формату `[DD.MM.YYYY HH:MM] Ім'я відправника:` (наприклад, `[10.07.2026 20:44] Віталій . Время перемен:`).
- **ПРАВИЛО**: Будь-який вхідний текст з Telegram **ОБОВ'ЯЗКОВО** чиститься на самому початку за допомогою `SYH_UTILS.cleanTelegramHeaders(text)` ДО розбиття на секції або блоки питань.
- **ЧОМУ**: Якщо не очистити текст спочатку, то таймкод з ніком, що з'явився всередині довгого питання (коли Telegram розбив його при надсиланні на 2 повідомлення), розірве це питання на декілька окремих питань.

### 2. Особливість кириличних регулярних виразів в JS (`\b`)
- У JavaScript регулярних виразах границя слова `\b` розрахована лише на ASCII символи (`[a-zA-Z0-9_]`).
- **ПРАВИЛО**: **НЕ використовуйте `\b` для кириличних слів** (наприклад, `\bВопросы` чи `\bПредложения`). Для кирилиці слід використовувати lookahead/lookbehind або звичайний пошук: `(?=[❓🙏]|Вопросы к|Вопросы на|Предложения по)`.

### 3. Сумісність з Node.js під час виконання Unit-тестів
- При розробці парсерів пам'ятайте, що unit-тести виконуються у середовищі Node.js (`test_parsers.js`), де браузерні глобальні змінні на кшталт `window` або `SYH_CONFIG` можуть бути відсутні або оголошені через `global`.
- **ПРАВИЛО**: Завжди використовуйте безпечну перевірку типу перед зверненням до конфігу:
  ```javascript
  const maxLen = (typeof SYH_CONFIG !== 'undefined' && SYH_CONFIG?.LIMITS?.TEXT_TRUNCATION_LENGTH) || 
                 (typeof window !== 'undefined' && window.SYH_CONFIG?.LIMITS?.TEXT_TRUNCATION_LENGTH) || 195;
  ```

### 4. Збереження суцільності та авторів питань
- Текст питань після першого рядка (автора) може містити довільні перенесення рядків. Усі наступні рядки до наступного номеру питання відносяться до тексту поточного питання.
