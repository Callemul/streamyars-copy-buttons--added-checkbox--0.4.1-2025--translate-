# Інструкція для ШІ та розробників (Developer & AI Guidelines)

## Правила парсингу та обробки списків питань / молитов z Telegram

### 1. Початкова очистка скопійованого тексту (`cleanTelegramHeaders`)
- При копіюванні довгих повідомлень або декількох повідомлень з Telegram до тексту додаються службові заголовки формату `[DD.MM.YYYY HH:MM] Ім'я відправника:` (наприклад, `[10.07.2026 20:44] Віталій . Время перемен:`).
- **ПРАВИЛО**: Будь-який вхідний текст з Telegram **ОБОВ'ЯЗКОВО** чиститься на самому початку за допомогою `SYH_UTILS.cleanTelegramHeaders(text)` ДО розбиття на секції або блоки питань.
- **ЧОМУ**: Якщо не очистити текст спочатку, то таймкод з ніком, що з'явився всередині довгого питання (коли Telegram розбив його при надсиланні на 2 повідомлення), розірве це питання на декілька окремих питань.

### 2. Особливість кириличних регулярних виразів в JS (`\b`)
- У JavaScript регулярних виразах границя слова `\b` розрахована лише на ASCII символи (`[a-zA-Z0-9_]`).
- **ПРАВИЛО**: **НЕ використовуйте `\b` для кириличних слів** (наприклад, `\bВопросы` чи `\bПредложения`). Для кирилиці слід використовувати lookahead/lookbehind або звичайний пошук: `(?=[❓🙏]|Вопросы к|Вопросы на|Предложения по)`.

### 3. Сумісність з Node.js під час виконання Unit-тестів
- При розробці парсерів пам'ятайте, що unit-тести виконуються у середовищі Node.js (`test_parsers.js`), де браузерні глобальні змінні на кшталт `window` або `SYH_CONFIG` можуть бути відсутні або оголошені через `global`.
- **ПРАВИЛО**: Завжди використовуйте безпечну перевірку типу перед зверненням до конфігу:
  ```javascript
  const maxLen = (typeof SYH_CONFIG !== 'undefined' && SYH_CONFIG?.LIMITS?.TEXT_TRUNCATION_LENGTH) || 
                 (typeof window !== 'undefined' && window.SYH_CONFIG?.LIMITS?.TEXT_TRUNCATION_LENGTH) || 195;
  ```

### 4. Збереження суцільності та авторів питань
- Текст питань після першого рядка (автора) може містити довільні перенесення рядків. Усі наступні рядки до наступного номеру питання відносяться до тексту поточного питання.

### 5. Помічник коментарів та Тригерні слова (Comment Assistant)
- **Файл модуля**: [modules/comment_assistant.ts](file:///d:/Chrome%20Extension/%D0%92%D1%80%D0%B5%D0%BC%D1%8F%20%D0%BF%D0%B5%D1%80%D0%B5%D0%BC%D0%B5%D0%BD.%20Chrome%20Extension/streamyars-copy-buttons%20%28added%20checkbox%29%200.6-2026.01.11/modules/comment_assistant.ts) (`SYH_COMMENT_ASSISTANT`).
- **Конфігурація тригерів**: `TRIGGER_WORDS` у [modules/config.ts](file:///d:/Chrome%20Extension/%D0%92%D1%80%D0%B5%D0%BC%D1%8F%20%D0%BF%D0%B5%D1%80%D0%B5%D0%BC%D0%B5%D0%BD.%20Chrome%20Extension/streamyars-copy-buttons%20%28added%20checkbox%29%200.6-2026.01.11/modules/config.ts) (наприклад `['вопрос']`).
- **Логіка роботи**:
  1. Кожен коментар сканується на наявність слів з `TRIGGER_WORDS` з підтримкою кириличних меж (`(?<![\\p{L}\\p{N}])слово(?![\\p{L}\\p{N}])`).
  2. Якщо тригерне слово знайдене, воно підсвічується за допомогою `<mark class="syh-trigger-highlight" data-syh-trigger="тригер">слово</mark>`.
  3. **ПРАВИЛО ПІДСПІЧУВАННЯ**: Підсвічування тригерних слів (хайлайт) **ніколи не повинно зникати** з тексту коментаря. Навіть якщо встановлено галочку чекбокса "Опрацьовано" (вручну або через перехоплювач ПКМ), хайлайт має залишатися видимим.
  4. На елемент коментаря додається атрибут `data-syh-triggered="вопрос"`, що дозволяє іншим ШІ та скриптам легко виявляти активовані тригери у DOM.

### 6. ЗОЛОТИЙ СТАНДАРТ РОБОТИ З DOM СТОРdict СТОРІНОК (NO BLIND SELECTORS POLICY)

> [!IMPORTANT]
> **ОБОВ'ЯЗКОВЕ ПРАВИЛО ДЛЯ БУДЬ-ЯКОГО ШІ ТА РОЗРОБНИКА НА ЦЬОМУ ПРОЄКТІ:**

1. **ЗАБОРОНА ВИГАДУВАННЯ СЕЛЕКТОРІВ НАОСЛІП**:
   - Жоден ШІ не має права припускати DOM-селектори сторонніх сайтів (StreamYard), вигадувати ідеалізовані класи або атрибути (на кшталт `div[role="dialog"][aria-label="..."]`), спираючись лише на здогадки.
2. **ПРОТОКОЛ "DEVTOOLS GOLDEN SNAPSHOT"**:
   - Усі селектори для робочих елементів StreamYard (AFK-діалоги, коментарі, банери) мають писатися **ВИКЛЮЧНО** на основі реальних HTML-дампів з DevTools (Chrome Inspect Element).
   - Базові HTML-дампи зберігаються у [docs/dom_snapshots/](file:///d:/Chrome%20Extension/%D0%92%D1%80%D0%B5%D0%BC%D1%8F%20%D0%BF%D0%B5%D1%80%D0%B5%D0%BC%D0%B5%D0%BD.%20Chrome%20Extension/streamyars-copy-buttons%20%28added%20checkbox%29%200.6-2026.01.11/docs/dom_snapshots/README.md). Будь-який новий ШІ при вході на проєкт **ЗОБОВ'ЯЗАНИЙ** спочатку прочитати ці зразки.
3. **ОБОВ'ЯЗКОВИЙ ДВОХРІВНЕВИЙ BULLETPROOF FALLBACK**:
   - Навіть маючи точні селектори, код **ОБОВ'ЯЗКОВО** мусить містити резервний незалежний алгоритм сканування елементів (за ключовими словами в усіх клікабельних вузлах та/або імітацією активності `mousemove`), щоб будь-які майбутні оновлення StreamYard НЕ могли зламати розширення.

## 🛠️ Як ШІ швидко знаходити код у проекті (AI Search Rules)

Щоб уникнути довгих пошуків, зависань і переповнення контексту токенами при роботі з цим проектом, ШІ-асистент повинен дотримуватися наступних правил пошуку:

1. **Ігнорування згенерованих файлів**:
   - Папка `dist/` містить скомпільовані та мініфіковані скрипти розширення (деякі важать понад 1 MB). Будь-який глобальний пошук (`grep`/`find`) без фільтрації буде забивати видачу гігантськими рядками згенерованого коду.
   - Завжди виключайте `dist/` та `node_modules/` зі шляхів пошуку (вони вже додані в `.clineignore` та `.kilocodeignore`).
2. **Структура сирцевого коду**:
   - Увесь основний вихідний код розширення (TypeScript) знаходиться в папці `modules/`.
   - Сторонні бібліотеки та допоміжні файли лежать у `lib/`.
   - Сторінки та інтерфейс попапу/опцій лежать у `popup/` та `options/`.
3. **Регулярні вирази**:
   - При пошуку по проекту за допомогою `grep_search` завжди вказуйте конкретні файлові маски або шукайте безпосередньо в директорії `modules/` (наприклад, `SearchPath: ".../modules"`), щоб миттєво знайти потрібне місце.

## 🗄️ Правила роботи зі сховищем (Storage Contract)

### Хто що використовує:
| Контекст            | Метод доступу              | Причина |
|---------------------|----------------------------|---------|
| Контент-скрипти (modules/) | import SYH_STORAGE | єдиний централізований адаптер |
| Popup (popup/*.js)  | chrome.storage.local напряму | popup context ніколи не zombie |
| YouTube (youtube/)  | import SYH_STORAGE | аналогічно до modules/ |

### ЗАБОРОНЕНО:
- ❌ localStorage fallback у SYH_STORAGE (ламає синхронізацію при zombie context)
- ❌ window.SYH_STORAGE || ланцюжки у модулях (маскують помилки)
- ❌ Прямий chrome.storage.local у контент-скриптах (обходить централізований адаптер)

### Як debugити zombie context:
Відкрий DevTools → Console на вкладці streamyard.com.
Якщо видно: [SYH Storage] chrome.storage not available — це zombie context.
Натисни Reload в chrome://extensions або перезавантаж сторінку.
