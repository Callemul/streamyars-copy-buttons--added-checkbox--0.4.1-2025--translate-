# Development Issues & Lessons Learned

## 1. YouTube Studio Tooltip Error (`Error: rp`)
- **Trigger**: Hovering over the creator heart (like button) on comment rows.
- **Symptoms**: Console logs `Name: Error\nMessage: rp...` sporadically (≈6 times per 40 comments).
- **Impact**: Does **not** break extension functionality (checkboxes still toggle) but pollutes the console.
- **Resolution**: Documented as a known YouTube Studio bug; optional non‑intrusive `window.addEventListener('error', …)` filter can be added but left disabled by default.
- **Recommendation**: Future AI agents should **first check the console for this error** before assuming their own code is broken.

---

## 2. Polymer `<iron-list>` Virtualization & Scroll Handling
- **Problem**: DOM nodes for comment rows are recycled; `MutationObserver` on `childList` does not fire on scroll, causing injection logic to miss newly visible rows.
- **Solution**: Use a **capture‑phase `scroll` listener on `window`** (`window.addEventListener('scroll', scrollHandler, { capture: true, passive: true })`). This ensures our code runs on every scroll event regardless of DOM recycling.
- **Lesson**: Always account for virtualized lists in YouTube Studio – rely on scroll events rather than DOM mutations.

---

## 3. Context‑Menu (`right‑click`) Interception
- **Issue**: Right‑click on comments sometimes failed after scrolling because the event listener was attached to individual comment elements that got recycled.
- **Fix**: Register a **global capture‑phase `contextmenu` listener** (`window.addEventListener('contextmenu', contextMenuHandler, { capture: true })`). This captures the event before YouTube’s own handlers and works across all scroll states.
- **Note**: The handler simply toggles the checkbox state; it does not interfere with native tooltips.

---

## 4. Polling Interval Management
- **Bug**: Old interval IDs were not cleared when the module stopped, leading to stray `setInterval` executions after navigation away from the comments page.
- **Fix**: Store the interval ID in `this.pollInterval` and clear it in `stopModule()` (`clearInterval(this.pollInterval); this.pollInterval = null;`).
- **Best Practice**: Always clean up timers, listeners, and global state in `stopModule()` to avoid memory leaks.

---

## 5. Event Listener Cleanup
- **Problem**: Listeners (`scrollHandler`, `contextMenuHandler`, `windowErrorHandler`) were added on `startModule()` but not always removed on `stopModule()`, causing duplicate handling when the module restarts.
- **Resolution**: Added explicit removal for each listener in `stopModule()` and set the stored references to `null`.

---

## 6. Inconsistent UI Feedback
- **Observation**: Checkboxes sometimes appeared unchecked visually while the internal state (`chk.checked`) was `true`. This stemmed from delayed UI updates due to the virtualized list.
- **Mitigation**: Force a UI refresh after toggling by calling `requestAnimationFrame` (or a small `setTimeout`) to ensure the DOM reflects the new state.

---

## 7. Development Workflow Lessons
- **Avoid “blind” edits**: Re‑reading the console and reproducing the issue with a dedicated DevTools script is essential before changing code.
- **Use diagnostic scripts**: Provide the user with a small snippet to capture current comment objects, tooltip errors, and event propagation status.
- **Document every edge case**: As we saw, many quirks are platform‑specific (Polymer, YouTube Studio internals). Keeping a living knowledge‑base prevents future AI agents from looping over the same fixes.

---

## 8. Recommendations for Future AI Agents
1. **Run a diagnostic script first** (see `diagnostic_script.js` in the skill resources) to collect live data about the page.
2. **Check the console for the `Error: rp`** before assuming a bug in our extension.
3. **Prefer capture‑phase global listeners** for events that need to survive DOM recycling.
4. **Always clean up** timers and listeners in `stopModule()`.
5. **Log actions** (e.g., when a checkbox is toggled) to aid future debugging.
6. **Update the project knowledge base** (`docs/knowledge/`) with these findings to avoid repeated “circle” debugging.
